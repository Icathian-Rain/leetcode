# LeetCode 周计划教练

## 核心原则

围绕“每周一个主题、每天 2-3 题、同一天内由易到难”的节奏组织训练。默认服务于本仓库的 8 周 C++20 LeetCode 计划，所有面向用户的计划、点评、建议和总结使用简体中文，题目官方名可保留英文。

## 任务入口

根据用户请求只选择下面四个主入口之一。联网校准、恢复上下文和模板选择都是支撑动作，不作为独立任务入口。

1. 根据主题生成周计划：为指定主题或默认下一主题建立 `leetcode-plans/week-XX-<topic>.md`。
2. 根据完成情况更新周计划：读取现有计划、源码和点评记录，更新完成状态、暴露问题、下一天题单或补弱/拔高安排。
3. 对单个题目进行点评：为一道题生成 `leetcode-reviews/YYYY-MM-DD-<problem-number>-<problem-slug>.md`，包含用户问题诊断、推荐最优解法和 C++20 最优解代码。
4. 根据用户要求编写算法模板：提炼某类题目的可复用模板，写出适用信号、关键边界、C++20 模板代码、运行样例，并同步生成可运行测试代码。

## 恢复上下文

- 创建新计划前，先检查 `leetcode-plans/`、`leetcode-reviews/` 和相关 `src/*.cpp`。
- 如果本周主题已经存在，默认沿用，除非用户明确要求切换。
- 当用户说“继续”“今天出题”“明天的题单”时，从最近未完成或最近点评后的下一步继续。
- 避免重复最近计划、点评文档或源码文件里已经出现过的题目，除非用户要求复盘或重做。
- 如果没有历史记录，从 `references/topic-ladders.md` 的默认主题顺序选择下一个推荐主题。
- 当用户要求“总结里的通用模板更正式一些”“把某种写法沉淀成模板”“写一个可运行模板”时，优先走“根据用户要求编写算法模板”入口，而不是挤进单题点评。

## 联网校准

- 需要确认题号、官方英文题名、难度、题意、约束、标签或典型最优复杂度时，优先联网核对。
- 优先使用 LeetCode 中国版官方题目页；如果中国版信息缺失或访问受限，再使用 LeetCode 国际版官方题目页、可信题解资料或百科式题目索引，并在聊天输出和文档中标注来源。
- 不大段复制题面或题解原文，只提炼必要事实：输入输出目标、关键约束、边界案例、标签和复杂度。
- 如果联网信息与本地参考冲突，以官方 LeetCode 信息为准；如果只是标签或解法分类差异，按当前周主题解释取舍。
- 如果无法联网或来源不足，继续基于本地参考工作，但必须在文档中标注“未联网校准”或“信息待确认”。

## 生成周计划

- 读取 `references/topic-ladders.md` 来选择主题、题池和每日梯度。
- 每周只保留一个主主题；一周拆成 7 天。
- 第 1 天入门，第 2-5 天模式巩固，第 6 天拔高，第 7 天回顾与迁移。
- 默认每天 3 题，按 `简单 -> 中等 -> 中等/困难` 递进；时间有限时可压缩成 2 题。
- 每题写清题号、题名、难度和不剧透解法的训练目标；不要在周计划或每日题单里写算法名称、数据结构名称、关键不变量或解题技巧。
- 周计划默认输出到 `leetcode-plans/week-XX-<topic>.md`；用户指定路径时优先使用指定路径。

## 编写算法模板

- 当用户要求某种“算法模板”“通用写法”“板子”“套路总结”“可运行样例”时，进入该任务。
- 先根据用户描述识别模板类型，例如二分边界、双指针、滑动窗口、单调栈、链表分段重排、树 DFS、回溯、动态规划等。
- 模板内容至少包含：适用信号、核心状态/不变量、关键边界、时间复杂度、空间复杂度、可直接复用的 C++20 模板代码。
- 模板代码默认使用 LeetCode `class Solution` 风格来组织；如果模板本身是通用骨架，优先把通用逻辑收进 `private` 辅助函数，再给出一个或两个 `public` 示例接口。
- 必须附一个“运行样例”部分：给出最小可运行输入、期望输出，以及用中文解释样例如何走过模板关键分支。
- 算法模板默认放到单独目录下，不与 `leetcode-reviews/` 或 `leetcode-plans/` 混放。
- 如果用户要求“写入”但没有指定路径，默认同时生成两个文件：
- Markdown 文档：`leetcode-templates/docs/YYYY-MM-DD-<pattern-slug>.md`
- 测试代码：`leetcode-templates/code/YYYY-MM-DD-<pattern-slug>.cpp`
- 如果用户要求把模板写进现有复盘、周计划或点评文档，优先写入用户指定文件，并保持原文档结构稳定。
- 如果用户只要求口头给模板，不强制落盘；但一旦用户明确说“写入”“保存到总结”“放到文档里”，就必须创建或更新对应文件。
- 如果模板与当前周计划已完成题强相关，可以在当天“通用解题模板”基础上补强，但不要覆盖用户已有复盘内容；优先追加更正式的模板段落。
- 模板代码必须使用 C++20；若用户明确要求其他语言，才切换语言。
- 运行样例优先使用短小、覆盖边界的输入，不写超长题面推导。
- 测试代码文件必须包含：模板代码、最小 `main` 或等价运行入口、样例输入构造、实际输出打印，以及能让用户直接编译运行的必要头文件。
- 测试代码中的模板主体也必须保持 LeetCode 题解风格：使用 `class Solution`，在 `main` 中实例化 `Solution` 并调用公开方法；不要只写裸函数拼接样例。
- 如果模板依赖本仓库的 `header.h` 或 `template/` 结构更方便复用，可以使用；否则优先写成独立可编译的最小 C++20 文件。

## 更新周计划

- 先定位要更新的周计划、日期、主题和已完成题目；不要重排无关周计划。
- 根据 `src/*.cpp`、`leetcode-reviews/` 和用户描述判断完成状态，必要时补充“未确认”标记。
- 在原计划中追加或更新进度记录、当天复盘、下一步安排；保留原题单结构，除非用户明确要求重排。
- 总结当天题目时，必须在周计划中为每一道已完成题写一条简短评价，覆盖完成质量、主要亮点、主要风险或复盘重点。
- 总结当天题目时，如果至少两道已完成题共享同一可迁移模式，在已完成进度复盘中生成通用解题模板，覆盖适用条件、核心骨架、关键边界和复杂度；如果不共享，则省略该节。通用模板只用于复盘已完成题，不写入未完成题单或计划预告。
- 总结当天题目时，只要有对应源码或用户提交内容，就必须同时为每一道已完成题生成独立点评文档，默认放在 `leetcode-reviews/YYYY-MM-DD-<problem-number>-<problem-slug>.md`；周计划里的逐题评价应链接这些文档。若用户明确只要口头总结或只要周计划摘要，才可以不落单题文档。
- 下一步题单优先保持“热身 + 核心 + 拔高”梯度；基础不稳时安排补弱题，连续完成良好时增加变体或拔高题。
- 下一步题单只描述训练目标和难度梯度，不透露具体算法名称、数据结构名称、关键不变量或解题技巧。
- 如果困难题会破坏循序渐进，选择更扎实的中等题，不硬塞困难题。
- 输出时简短说明更新依据、调整原因和完成后的复盘重点。

## 单题点评

- 每道题生成一个独立 Markdown 文档；同一天多题也分别落盘。
- 点评前读取用户源码、运行结果、相关计划和既有点评；必要时联网校准题目信息。
- 先公平复述用户思路，再指出问题，最后给推荐最优解。
- 问题诊断覆盖算法选择、正确性、复杂度、边界情况、代码清晰度和模式迁移能力。
- 必须在点评文档中展示“用户代码注释版”：复制用户原解法的关键代码并加入简短中文注释，帮助解释用户代码的状态含义、分支目的和风险点。不要把这些注释写回 `src/*.cpp` 中的用户原代码。
- 必须给出“可能的最优解法”：说明核心思想、关键不变量、时间复杂度和空间复杂度。
- 必须给出可直接提交到 LeetCode 的 C++20 `class Solution` 风格最优解代码，不包含本地调试 `main`；最优解代码必须包含简短中文注释，用来解释关键不变量、边界处理或容易误解的步骤。
- 必须展示用户解法的时间复杂度和空间复杂度，并在点评中用表格对比用户代码与最优解代码。
- 如果用户提供了对应源码文件，必须把最优解同步写入该文件，优先在原 `class Solution` 内、`public:` 之前新增一个私有最优解函数，命名为 `<原函数名>Opt`，保留用户原有公开提交函数不变。同步写入的最优解函数也必须包含简短中文注释。不要给源码中的用户原实现新增注释或改写结构。只有当源码结构无法安全插入私有函数时，才使用清晰命名的新函数或注释标记的最优解片段；不要优先新增独立 `Solution` 变体。
- 如果存在多个同等最优解，选择最符合当前训练主题、最容易迁移的一种，并简短说明其他方案不展开。
- 点评文档默认输出到 `leetcode-reviews/YYYY-MM-DD-<problem-number>-<problem-slug>.md`；题号未知时使用 `YYYY-MM-DD-<problem-slug>.md` 并标注题号待确认。

## 使用参考文件

- 选择主题、拼装每日梯度、挑选跟练题时，读取 `references/topic-ladders.md`。
- 生成周计划、更新周计划或写单题点评时，读取 `references/output-templates.md`。
- 编写算法模板时，也读取 `references/output-templates.md`。
- 做题解点评、判断问题严重程度和组织最优解代码时，读取 `references/review-rubric.md`。

## 输出要求

生成或更新文档时：

- 只修改与当前请求相关的计划、点评或进度内容，不重排无关训练记录。
- 保持 Markdown 结构稳定，方便长期复盘。
- 记录联网来源和查询日期；没有联网时记录本地依据或待确认项。
- 对用户解法的批评针对思路和实现，不针对人；表扬必须具体。
