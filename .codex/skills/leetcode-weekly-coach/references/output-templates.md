# 输出模板

在生成周计划或题解点评文档时，使用下面的模板。整体语气保持简洁、具体、鼓励式。

- <模式或概念>
- <模式或概念>

## 每日计划

3. `<题目名称>` (`中等` 或 `困难`) - <为什么它适合作为拔高题>

## 题解点评模板

```md
# 题解点评 - <题目名称>

## 基本信息

- 日期：<YYYY-MM-DD>
- 主题：<主题>
- 难度：<难度>
- 本次结果：<通过 / 错误答案 / 超时 / 未完成 / 仅有思路>

## 用户思路概述

<先公平、准确地复述用户做法，再进入评价。>

## 评价

- 题意理解：<很好 / 较好 / 一般 / 需要加强> - <原因>
- 思路质量：<...> - <原因>
- 正确性：<...> - <原因>
- 复杂度意识：<...> - <原因>
- 边界覆盖：<...> - <原因>
- 代码清晰度：<...> - <原因>
- 当前最重要的成长点：<一句话点出最优先改进方向>

## 做得好的地方

- <具体优点>
- <具体优点>

## 需要改进的地方

- <具体问题>
- <具体问题>

## 下一步建议

<用一小段话给出最值得执行的下一步动作。>

## 后续练习

1. `<题目名称>` - <为什么它适合紧接着练>
2. `<题目名称>` - <为什么它适合作为迁移练习>
```

## 文件命名

除非用户指定了其他位置，否则默认使用：

- 周计划：`leetcode-plans/week-XX-<topic>.md`
- 题解点评：`leetcode-reviews/YYYY-MM-DD-<problem-slug>.md`

## 语言规则

- 标题、说明、评价、建议、总结全部使用简体中文。
- 题目名可以保留 LeetCode 官方英文标题，必要时补一句中文说明。
- 只有当用户明确要求其他语言时，才切换输出语言。

## 点评语气规则

- 表扬要具体，不要空泛。
- 批评针对思路和实现，不针对人。
- 最重要的问题放前面。
- 即使答案完全错误，也保持支持性和建设性。
