## 用户思路概述

你把所有数字放进 `unordered_set`，然后从 `1` 枚举到 `n + 1`，返回第一个不在集合里的正整数。这个做法抓住了一个正确结论：长度为 `n` 的数组里，第一个缺失正数一定在 `[1, n + 1]` 范围内。

因此，从正确性角度看，这个解法很稳；问题主要在空间复杂度没有达到本题要求。

## 主要问题

- 空间复杂度未达标：`unordered_set` 需要 `O(n)` 额外空间，而本题的核心挑战是在线性时间内使用 `O(1)` 额外空间。
- 原地不变量还没有建立：这题想训练的是“值 `x` 如果落在 `[1, n]`，就应该被放到下标 `x - 1`”，而不是只判断存在性。
- 迁移价值不足：哈希集合版可以快速做对，但遇到 `448`、`442` 这类要求原地标记 / 原地放置的题时，还需要补上数组下标与值之间的映射意识。

## 做得好的地方

- 正确识别了答案范围 `[1, n + 1]`，这一步是本题推导的基础。
- 哈希集合版逻辑直接，不会被负数、零、重复值干扰。
- 先保证正确性再追求空间优化，这个推进顺序是合理的；现在正好进入本题真正的训练点。

## 最优解法

推荐使用原地放置。数组长度为 `n` 时，只有 `1..n` 这些值会影响答案；值 `x` 应该放到下标 `x - 1`。遍历数组时，只要 `nums[i]` 在 `[1, n]` 内，且目标位置还不是这个值，就把它交换过去。交换完成后，第二次遍历中第一个 `nums[i] != i + 1` 的位置就是答案。

关键不变量：如果某个值 `x` 能被正确放置，最终它会出现在 `nums[x - 1]`；如果目标位置已经是 `x`，说明遇到重复值，必须停止交换避免死循环。

- 时间复杂度：`O(n)`，每次交换都会让至少一个有效值归位
- 空间复杂度：`O(1)`

## 最优解代码

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();

        for (int i = 0; i < n; ++i) {
            while (nums[i] >= 1 && nums[i] <= n &&
                   nums[nums[i] - 1] != nums[i]) {
                swap(nums[i], nums[nums[i] - 1]);
            }
        }

        for (int i = 0; i < n; ++i) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }

        return n + 1;
    }
};
```
