## 用户思路概述

你把四个数组拆成两组：先枚举 `nums1 + nums2` 的所有 pair sum，并用哈希表记录每个和出现的次数；再枚举 `nums3 + nums4`，查询是否存在互补值 `-(num3 + num4)`。找到后把对应频次累加到答案里。

这正是本题最核心的降维思路：把 `O(n^4)` 的四重枚举压成两个 `O(n^2)` 的 pair sum 问题。

## 主要问题

- 整体算法没有阻塞级问题：当前做法命中了本题最优复杂度，能处理重复值，因为哈希表存的是 sum 的出现次数而不是只存是否存在。
- 小的实现细节可以更顺：`if (cnt.find(target) != cnt.end()) ans += cnt[target];` 是正确的，但可以直接写 `ans += cnt[-num3 - num4];`，代码更短。不过这种写法会给不存在的 key 插入 `0`，在复盘时要知道它的副作用。
- 整数范围目前安全：题目约束下单次四数和在 `int` 内，答案也保证在 `int` 范围内。你这里使用 `int` 没问题，但以后如果遇到更大约束，要主动切到 `long long`。

## 做得好的地方

- 能主动把四数组组合转成“两两配对 + 哈希频次”，这是本题最值得迁移的模式。
- 频次表使用正确，没有把重复 pair sum 丢掉，所以能正确统计多个不同下标组合。
- 控制流很干净，两个双层循环分别负责建表和查表，复盘成本低。

## 最优解法

推荐最优解仍然是当前这种 pair sum 哈希频次。关键不变量是：`sumCount[s]` 始终表示前两个数组中和为 `s` 的下标对数量；当后两个数组产生和 `t` 时，能与它组成 0 的前半部分数量就是 `sumCount[-t]`。

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n^2)`

## 最优解代码

```cpp
class Solution {
public:
    int fourSumCount(vector<int>& nums1, vector<int>& nums2,
                     vector<int>& nums3, vector<int>& nums4) {
        unordered_map<int, int> sumCount;

        for (int a : nums1) {
            for (int b : nums2) {
                ++sumCount[a + b];
            }
        }

        int ans = 0;
        for (int c : nums3) {
            for (int d : nums4) {
                auto it = sumCount.find(-c - d);
                if (it != sumCount.end()) {
                    ans += it->second;
                }
            }
        }

        return ans;
    }
};
```
