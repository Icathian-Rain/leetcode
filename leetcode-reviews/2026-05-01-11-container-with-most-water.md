## 用户思路概述

你把两个指针放在数组两端，每次用当前宽度和两侧较短高度计算容量并更新答案。随后移动高度较小的一侧，因为容量受短板限制，保留短板并缩小宽度不可能得到更大面积。

这命中了本题最关键的贪心双指针依据：移动短板，而不是盲目枚举所有边界。

## 主要问题

- 整体算法正确，没有阻塞级问题，时间复杂度达到最优。
- 代码里直接写 `if (height[i] < height[j]) i++; else j--;` 是正确的，但建议复盘时明确说明：当两边相等时移动任意一边都可以，因为宽度变小后，若不找到更高的边，面积不会变大。
- 当前变量名 `i`、`j` 可以接受；如果写复盘或面试白板，`left`、`right` 更能表达边界含义。

## 做得好的地方

- 每轮先用当前边界更新答案，再移动指针，没有漏掉初始最大宽度候选。
- 正确移动较短边，保留了可能提升高度的机会。
- 空间使用为常数，没有引入不必要的辅助数组。

## 最优解法

推荐最优解就是双指针 + 短板移动。关键不变量是：当前面积由较短柱子决定；如果移动较高柱子，宽度一定变小，而短板高度不变或更低，面积不可能超过当前组合。因此每一步都可以安全排除当前较短边。

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 最优解代码

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int left = 0;
        int right = static_cast<int>(height.size()) - 1;
        int best = 0;

        while (left < right) {
            int width = right - left;
            int boundedHeight = min(height[left], height[right]);
            best = max(best, width * boundedHeight);

            if (height[left] <= height[right]) {
                ++left;
            } else {
                --right;
            }
        }

        return best;
    }
};
```

## 对比与改进方向

你的实现和最优解一致。下一步要强化的是证明能力：不是因为“短的看起来该移动”，而是因为固定短板时，继续缩小宽度没有机会改善答案，只有换掉短板才可能得到更大面积。
