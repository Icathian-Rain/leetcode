## 用户思路概述

1. 使用 `pos` 指向 `nums1` 最后一个写入位置，`p1` 指向 `nums1` 有效区末尾，`p2` 指向 `nums2` 末尾。
2. 从后往前循环填充 `nums1[pos]`。
3. 当某一侧耗尽时，直接从另一侧继续取元素。
4. 当两侧都还有元素时，把较大的那个放到当前位置，并移动对应指针。

## 用户解法复杂度

- 时间复杂度：`O(m + n)`
- 空间复杂度：`O(1)`
- 复杂度来源：`pos` 从 `m + n - 1` 递减到 `0`，每次写入一个元素；只使用常数个指针变量。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不要把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        // pos 是当前写入位置，p1/p2 分别指向两个有序段的最大未处理元素。
        for (int pos = m + n - 1, p1 = m - 1, p2 = n - 1; pos >= 0; pos--) {
            if (p1 < 0) {
                // nums1 有效元素已用完，只能继续填 nums2。
                nums1[pos] = nums2[p2];
                p2--;
            } else if (p2 < 0) {
                // nums2 已用完，nums1 剩余元素本来就在正确位置。
                nums1[pos] = nums1[p1];
                p1--;
            } else if (nums1[p1] > nums2[p2]) {
                // 从后往前放较大值，避免覆盖 nums1 中还没比较的元素。
                nums1[pos] = nums1[p1];
                p1--;
            } else {
                nums1[pos] = nums2[p2];
                p2--;
            }
        }
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 从后往前写 | 使用 `pos` 从尾部填充。 | 避免覆盖 `nums1` 前 `m` 个未处理元素，是本题关键。 | 复盘时明确“为什么不能从前往后直接写”。 |
| 某一侧耗尽 | 分支覆盖 `p1 < 0` 和 `p2 < 0`。 | 正确性完整，能覆盖 `m = 0` 和 `n = 0`。 | `p2 < 0` 后其实可以提前结束，因为 `nums1` 剩余元素已经在原位。 |
| 控制流简洁度 | 一个 `for` 里处理所有情况。 | 正确但 `p2 < 0` 分支会做一些不必要的自赋值。 | 推荐最优写法只在 `p2 >= 0` 时循环。 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法 | 正确覆盖边界，从后往前写的方向很好。 | `p2` 用完后仍继续循环，做了不必要的 `nums1[pos] = nums1[p1]`。 | 提交可行，适合理解完整分支。 |
| 推荐最优解 | 只要 `nums2` 没合并完就继续，代码更短，少做无效写入。 | 需要理解 `nums1` 剩余元素已经天然有序且位置正确。 | 更适合面试和长期模板。 |

## 最优解法

1. 让 `p1` 指向 `nums1` 有效区末尾，`p2` 指向 `nums2` 末尾，`write` 指向总数组末尾。
2. 只要 `p2 >= 0`，就说明还有 `nums2` 元素必须放进 `nums1`。
3. 若 `p1 >= 0` 且 `nums1[p1] > nums2[p2]`，写入 `nums1[p1]`。
4. 否则写入 `nums2[p2]`。
5. 如果 `nums2` 已经写完，`nums1` 剩余元素保持原位即可。

- 最优时间复杂度：`O(m + n)`
- 最优空间复杂度：`O(1)`

### 最优解代码

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int p1 = m - 1;
        int p2 = n - 1;
        int write = m + n - 1;

        // 只要 nums2 没合并完，就必须继续从后往前填 nums1。
        while (p2 >= 0) {
            if (p1 >= 0 && nums1[p1] > nums2[p2]) {
                nums1[write] = nums1[p1];
                --p1;
            } else {
                nums1[write] = nums2[p2];
                --p2;
            }
            --write;
        }
    }
};
```

## 对比与改进方向

| 对比项 | 用户代码 | 最优解代码 | 改进方向 |
| --- | --- | --- | --- |
| 状态定义 | `pos` / `p1` / `p2` 清楚。 | `write` / `p1` / `p2` 同样清楚。 | 变量名可以更强调写入职责。 |
| 更新逻辑 | 四个分支覆盖所有情况。 | 两个分支处理必须写入的情况。 | 利用“nums1 剩余已在原位”减少分支。 |
| 边界处理 | `m = 0`、`n = 0` 都覆盖。 | 同样覆盖，且 `n = 0` 时循环不执行。 | 推荐用 `while (p2 >= 0)` 表达核心边界。 |
| 复杂度 | `O(m + n)` / `O(1)` | `O(m + n)` / `O(1)` | 复杂度相同，推荐解常数操作更少。 |
