## 用户思路概述

1. 用 `st` 保存正常栈元素，用 `minEle` 保存每一层对应的当前最小值。
2. 构造时先在 `minEle` 中放入 `INT_MAX` 作为哨兵，避免第一次 `push` 时辅助栈为空。
3. 每次 `push` 同时压入元素和新的最小值，每次 `pop` 同步弹出两个栈，保证层数一致。

## 用户解法复杂度

- 时间复杂度：所有接口均为 `O(1)`。
- 空间复杂度：`O(n)`。
- 复杂度来源：辅助栈为每个元素额外保存一个当前最小值快照。

## 用户代码注释版

```cpp
class MinStack {
    stack<int> st;     // 主栈保存真实元素
    stack<int> minEle; // 第 i 层保存压入第 i 个元素后的最小值
public:
    MinStack() {
        minEle.push(INT_MAX); // 哨兵让第一次 push 可以直接比较
    }

    void push(int val) {
        st.push(val);
        minEle.push(min(minEle.top(), val)); // 同步记录当前层最小值
    }

    void pop() {
        st.pop();
        minEle.pop(); // 必须和主栈同步弹出，否则 getMin 会错层
    }

    int top() {
        return st.top();
    }

    int getMin() {
        return minEle.top();
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 辅助状态同步 | 每次 `push/pop` 都同时更新两个栈 | `getMin` 始终能 `O(1)` 返回 | 继续保持“主状态变，辅助状态也变”的检查习惯。 |
| 重复最小值 | 使用每层最小值快照 | 能正确处理多个相同最小值 | 这是比只保存更小值更不容易写错的方案。 |
| 哨兵使用 | 用 `INT_MAX` 简化首次插入 | 代码简洁，但辅助栈会比主栈多一层 | 复盘时说明哨兵不代表真实元素即可。 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法 | 所有接口 `O(1)`，重复最小值处理稳定 | 辅助栈保存每层快照，空间为 `O(n)` | 本题最推荐、最稳的写法。 |
| 推荐最优解 | 与用户解法一致 | 可用“值 + 当前最小值”单栈合并，但收益不大 | 当前写法更适合训练状态同步。 |

## 最优解法

1. 主栈保存所有真实元素。
2. 辅助栈保存每个深度下的最小值快照。
3. 压入和弹出时两个栈同步变化，查询最小值时直接读取辅助栈栈顶。

- 最优时间复杂度：所有接口 `O(1)`
- 最优空间复杂度：`O(n)`

### 最优解代码

```cpp
class MinStack {
    stack<int> values;
    stack<int> mins;

public:
    MinStack() {
        mins.push(INT_MAX);
    }

    void push(int val) {
        values.push(val);
        // 每一层都保存当前最小值，弹出时自然回到上一层状态。
        mins.push(min(mins.top(), val));
    }

    void pop() {
        values.pop();
        mins.pop();
    }

    int top() {
        return values.top();
    }

    int getMin() {
        return mins.top();
    }
};
```
