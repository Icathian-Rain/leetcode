## 用户思路概述

1. 用栈保存括号下标，并先压入 `-1` 作为合法片段左边界前一位的哨兵。
2. 遇到 `(` 时，把当前下标入栈，等待后续右括号匹配。
3. 遇到 `)` 时，先弹出栈顶，表示尝试匹配一个左括号或移除旧边界。
4. 如果弹出后栈为空，说明当前右括号无法接在任何合法片段后面，把当前下标作为新的边界。
5. 如果栈不为空，当前合法片段长度就是 `i - st.top()`，用它更新答案。

## 用户解法复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`
- 复杂度来源：每个下标最多入栈和出栈一次；栈中保存尚未结算的边界下标。

## 用户代码注释版

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int n=s.length();
        stack<int> st; // 保存未匹配左括号下标，以及最近非法右括号边界。
        int ans=0;
        st.push(-1); // 哨兵：合法片段左边界的前一位。
        for(int i=0; i<n; i++) {
            if(s[i] == '(') {
                st.push(i);
            } else {
                st.pop(); // 尝试匹配最近的左括号，或弹出旧边界。
                if(st.empty()) {
                    st.push(i); // 当前右括号无法匹配，成为新的左边界。
                } else {
                    ans = max(ans, i-st.top()); // st.top() 是当前合法片段前一位。
                }
            }
        }
        return ans;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 哨兵边界 | 使用 `-1` 作为初始边界。 | 正确处理从下标 0 开始的合法片段。 | 复盘时说清栈顶不是总是左括号，也可能是最近非法右括号边界。 |
| 结算时机 | 每次合法匹配后用 `i - st.top()` 更新答案。 | 命中经典最优栈解。 | 重点理解为什么不是 `i - poppedIndex + 1`。 |
| 非法右括号 | 栈空后把当前下标压回去。 | 能正确切断前一段，开始新的候选区间。 | 这一步是本题最容易漏掉的边界。 |

## 最优解法

1. 栈中保存未匹配左括号下标，以及最近一次无法匹配的右括号下标。
2. 初始压入 `-1`，让从 0 开始的合法片段能被正确计算。
3. 遇到左括号入栈。
4. 遇到右括号先弹栈；如果栈空，当前右括号成为新边界；否则用当前下标减栈顶边界更新最长长度。

- 最优时间复杂度：`O(n)`
- 最优空间复杂度：`O(n)`

### 最优解代码

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        stack<int> indexes;
        indexes.push(-1);
        int ans = 0;

        for (int i = 0; i < (int)s.size(); ++i) {
            if (s[i] == '(') {
                indexes.push(i);
            } else {
                indexes.pop();
                if (indexes.empty()) {
                    // 当前右括号无法匹配，成为下一段合法区间的左边界。
                    indexes.push(i);
                } else {
                    ans = max(ans, i - indexes.top());
                }
            }
        }

        return ans;
    }
};
```
