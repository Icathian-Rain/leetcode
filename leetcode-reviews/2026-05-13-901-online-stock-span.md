## 用户思路概述

1. 用 `stock` 保存历史股票价格，当前价格下标为 `stock.size()`。
2. 用栈 `st` 保存还可能成为左侧边界的历史下标。
3. 新价格到来时，弹出所有价格小于等于当前价格的历史下标。
4. 如果弹出后栈为空，说明当前价格能覆盖之前所有天，跨度为 `idx + 1`。
5. 如果栈不为空，栈顶是左侧最近一个价格大于当前价格的下标，跨度为 `idx - st.top()`。

## 用户解法复杂度

- 单次 `next` 摊还时间复杂度：`O(1)`
- 总空间复杂度：`O(n)`
- 复杂度来源：每个历史下标最多入栈一次、出栈一次；`stock` 和栈保存历史信息。

## 用户代码注释版

```cpp
class StockSpanner {
public:
    vector<int> stock; // 保存每一天价格，便于通过下标查历史价格。
    stack<int> st;    // 保存价格严格大于后续被覆盖价格的下标。
    StockSpanner() {
    }

    int next(int price) {
        int idx=stock.size();
        while(!st.empty() && price >= stock[st.top()]) {
            st.pop(); // 被当前价格覆盖的历史天不会再成为边界。
        }
        int ans = idx+1;
        if(!st.empty()) {
            ans = idx - st.top(); // 左侧最近更高价格决定跨度边界。
        }
        stock.push_back(price);
        st.push(idx);
        return ans;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 单调状态 | 保存左侧仍可能作为边界的下标。 | 正确命中在线单调栈模式。 | 复盘时说清被弹出的价格已经被当前价格覆盖。 |
| 摊还复杂度 | 每个下标最多弹出一次。 | 虽然单次可能弹多个，但总复杂度线性。 | 设计题要区分单次最坏和摊还。 |
| 状态压缩 | 当前保存完整价格数组和下标栈。 | 正确但可以更紧凑。 | 可把价格和已经合并的跨度一起入栈，省掉 `stock` 数组。 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法 | 正确、直观，用下标计算跨度清楚。 | 需要额外 `stock` 数组；状态分散在两个结构中。 | 适合从 `739` 迁移过来的写法。 |
| 推荐最优解 | 栈中直接保存 `{price, span}`，弹出时合并跨度。 | 需要理解跨度可合并。 | 更贴合在线查询题，代码更短。 |

## 最优解法

1. 栈中保存若干对 `{price, span}`，表示这个价格已经合并了连续多少天。
2. 新价格到来时，先令当前跨度为 `1`。
3. 只要栈顶价格小于等于当前价格，就把栈顶跨度并入当前跨度并弹出。
4. 当前 `{price, span}` 入栈，返回 `span`。

- 最优摊还时间复杂度：每次 `next` 为 `O(1)`
- 最优空间复杂度：`O(n)`

### 最优解代码

```cpp
class StockSpanner {
    stack<pair<int, int>> spans;

public:
    StockSpanner() {
    }

    int next(int price) {
        int span = 1;
        while (!spans.empty() && spans.top().first <= price) {
            // 被当前价格覆盖的连续天数可以直接合并。
            span += spans.top().second;
            spans.pop();
        }
        spans.push({price, span});
        return span;
    }
};
```
