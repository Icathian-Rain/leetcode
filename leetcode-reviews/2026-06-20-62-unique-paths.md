## 用户思路概述

1. 使用 `dp[i][j]` 表示到达第 `i` 行第 `j` 列位置的路径数量。
2. 通过多开一行一列，把真实网格映射到 `1..m`、`1..n`，减少越界判断。
3. 初始化 `dp[1][1] = 1`，表示起点有一种到达方式。
4. 每个位置由上方和左方两个来源累加得到。
5. 返回右下角 `dp[m][n]`。

## 用户解法复杂度

- 时间复杂度：`O(m*n)`
- 空间复杂度：`O(m*n)`
- 复杂度来源：需要填完整个二维表，每个格子只计算一次。

## 用户代码注释版

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<vector<int>> dp(m+1, vector<int>(n+1, 0)); // 1-based padding，避免访问负下标。
        dp[1][1] = 1; // 起点只有一种路径。
        for(int i=1; i<=m; i++) {
            for(int j=1; j<=n; j++) {
                if(i==1&&j==1) continue; // 起点不需要从上/左转移。
                dp[i][j] = dp[i-1][j] + dp[i][j-1]; // 上方路径数 + 左方路径数。
            }
        }
        return dp[m][n];
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 状态定义 | `dp[i][j]` 表示到达当前位置的方案数 | 正确抓住二维位置状态 | 继续保持先定义坐标含义再写循环 |
| 初始化 | 起点单独置 1 | 起点不会被错误覆盖 | 也可以用首行首列全 1 的写法 |
| 边界处理 | 用额外边界行列规避越界 | 实现简洁稳定 | 复盘时说清真实坐标和 `dp` 坐标差一位 |
| 空间优化 | 使用完整二维表 | 便于理解，但空间可压缩 | 同一行从左到右更新时可用一维数组 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法 | 状态直观，边界处理稳 | 空间为二维表 | 学习网格 DP 时很适合 |
| 推荐最优解 | 保留同样转移，空间降为 `O(n)` | 需要理解一维数组同时保存上方和左方 | 提交和面试中更轻量 |

## 最优解法

1. 用一维数组 `dp[col]` 表示当前行到达该列的路径数。
2. 初始化第一行为 1。
3. 从第二行开始，`dp[col]` 原值是上方来源，`dp[col - 1]` 是左方来源。
4. 逐格累加后返回最后一列。

- 最优时间复杂度：`O(m*n)`
- 最优空间复杂度：`O(n)`

### 最优解代码

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<int> dp(n, 1);
        for (int row = 1; row < m; row++) {
            for (int col = 1; col < n; col++) {
                // dp[col] 是上方来源，dp[col - 1] 是左方来源。
                dp[col] += dp[col - 1];
            }
        }
        return dp[n - 1];
    }
};
```

## 对比与改进方向

| 对比项 | 用户代码 | 最优解代码 | 改进方向 |
| --- | --- | --- | --- |
| 状态定义 | 二维表记录每个位置 | 一维数组记录当前行 | 先理解二维，再压缩行 |
| 更新逻辑 | 上方 + 左方 | 上方 + 左方 | 转移本质相同 |
| 边界处理 | 额外行列 + 起点特判 | 第一行全 1 | 两种都可用 |
| 复杂度 | `O(m*n)` / `O(m*n)` | `O(m*n)` / `O(n)` | 空间可优化 |
