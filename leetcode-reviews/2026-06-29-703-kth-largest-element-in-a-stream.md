## 用户思路概述

1. 用一个小根堆保存当前数据流中最大的 `k` 个元素。
2. 构造函数先把初始数组全部放入堆，再不断弹出堆顶，直到堆大小不超过 `k`。
3. 每次 `add` 新值时先入堆，再把多余元素弹掉，最后返回堆顶作为当前第 `k` 大。

## 用户解法复杂度

- 时间复杂度：构造函数 `O(n log n)`，每次 `add` 为 `O(log k)` 到 `O(log n)`
- 空间复杂度：`O(k)`
- 复杂度来源：初始化阶段先把所有元素入堆，再裁剪到 `k`；后续堆大小稳定在 `k`。

## 用户代码注释版

```cpp
class KthLargest {
public:
    int k;
    priority_queue<int, vector<int>, greater<int>> pq; // 小根堆，保存当前最大的 k 个元素。

    KthLargest(int k, vector<int>& nums) {
        this->k = k;
        for(auto num: nums) {
            pq.push(num);
        }
        while(pq.size() > k) {
            pq.pop(); // 弹出最大的 k 个之外的较小候选。
        }
    }

    int add(int val) {
        pq.push(val);
        while(pq.size() > k) {
            pq.pop(); // 插入后仍然只保留 k 个最大候选。
        }
        return pq.top(); // k 个最大候选里最小的那个，就是整体第 k 大。
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 堆顶语义 | 能用小根堆保留前 `k` 大 | 正确命中数据流第 `k` 大的核心 | 复盘时明确说出“堆顶是前 `k` 大中的最小值” |
| 初始化方式 | 先全量入堆再裁剪 | 正确但初始化可进一步优化 | 可在入堆时同步裁剪，使构造复杂度保持 `O(n log k)` |
| 接口状态 | `k` 和堆作为对象状态保存 | 符合数据流题的长期查询要求 | 注意这类题不是单次函数，而是持续维护对象状态 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法 | 思路直接，`add` 逻辑稳定 | 构造阶段先全量入堆，略多做了一些工作 | 数据流持续追加且随时查询第 `k` 大 |
| 推荐最优解 | 入堆时同步裁剪，始终保持堆大小不超过 `k` | 需要先想清小根堆的堆顶语义 | 同本题，也是后续 Top K 题的标准骨架 |

## 最优解法

1. 对每个初始元素调用同一套 `add` 逻辑。
2. 堆中始终只保留当前最大的 `k` 个元素。
3. 当堆大小超过 `k` 时，弹出堆顶这个最小候选。
4. 每次查询时，堆顶就是当前第 `k` 大。

- 最优时间复杂度：构造函数 `O(n log k)`，每次 `add` 为 `O(log k)`
- 最优空间复杂度：`O(k)`

### 最优解代码

```cpp
class KthLargest {
    int limit;
    priority_queue<int, vector<int>, greater<int>> heap;

public:
    KthLargest(int k, vector<int>& nums) : limit(k) {
        for (int num : nums) {
            add(num);
        }
    }

    int add(int val) {
        heap.push(val);
        // 只保留当前最大的 k 个数，堆顶就是第 k 大。
        if (heap.size() > limit) {
            heap.pop();
        }
        return heap.top();
    }
};
```
