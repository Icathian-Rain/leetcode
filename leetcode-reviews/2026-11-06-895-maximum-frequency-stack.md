## 用户思路概述

1. 用 `freq[val]` 保存值 val 当前仍在结构中的出现次数。
2. 每次 push 先增加频次，再把 val 压入 `group[新频次]`，记录一次到达该频次的事件。
3. 用 `maxFreq` 直接定位当前最高频次，避免查找所有值或维护比较堆。
4. pop 取最高层栈顶，减去该值的一次出现；当前层为空时，最高频次减一。

## 用户解法复杂度

- push：哈希操作平均 O(1)，栈操作摊还 O(1)，因此平均摊还 O(1)。
- pop：平均 O(1)。这里的平均复杂度依赖 unordered_map；哈希严重冲突时不保证最坏单次 O(1)。
- 设累计 push 次数为 P，空间上界为 O(P)。设当前未弹出的元素数为 N，所有层中有效栈记录总数恰好为 N。
- 原实现保留零频 key 和空层；哈希键数量还依赖历史不同值数及历史最大频次，不能在结构弹空后仍简单宣称全部实际占用为 O(N)。

## 用户代码注释版

> 保留用户原解法结构，仅在文档中补充中文注释。

```cpp
class FreqStack {
    unordered_map<int, int> freq; // 每个值当前仍保留的出现次数。
    unordered_map<int, stack<int>> group; // 到达某频次的尚未撤销事件。
    int maxFreq;
public:
    FreqStack(): maxFreq(0) {

    }

    void push(int val) {
        freq[val]++;
        group[freq[val]].push(val); // 同频层内按到达时间后进先出。
        maxFreq = max(maxFreq, freq[val]);
    }

    int pop() {
        int val = group[maxFreq].top(); // 最高频优先，同频取最近事件。
        freq[val]--;
        group[maxFreq].pop();
        if(group[maxFreq].empty()) {
            maxFreq--; // 低一层已有先前保留的记录，无需重建。
        }
        return val;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 复盘重点 |
| --- | --- | --- | --- |
| 主优先级 | 用 maxFreq 定位最高层 | O(1) 定位候选层 | 频次每次只变 1，无需通用排序结构 |
| 次优先级 | 每层用 stack 保存事件顺序 | 自然满足同频时最近者优先 | 栈记录的是到达该层的历史事件 |
| 层的含义 | 旧层记录不移动、不删除 | 降频后直接恢复较低层的正确顺序 | group[f] 不是“当前频次恰为 f 的所有值” |
| 降频逻辑 | pop 后不把值压入低一层 | 避免重复记录及篡改时间顺序 | 弹出不是一次新 push，不能刷新低层顺序 |
| 空间回收 | 留下零频键与空层 | 不影响正确性，但容器随历史增长 | 可选清理用于明确状态，不是算法必需条件 |

## 算法优缺点

| 方案 | 优点 | 取舍 | 适用情况 |
| --- | --- | --- | --- |
| 用户频次分层栈 | 已达到标准最优级，主次优先级均直接表达 | 必须理解历史层记录，不能按互斥分组解释 | 本题每次增减一个副本 |
| 推荐频次分层栈 | 同一算法，顺便清理零频键和空层 | 仍依赖哈希平均复杂度，不保证容器容量立刻归还系统 | 希望长期操作后逻辑状态更紧凑 |
| 频次与时间戳堆 | 优先级规则显式，较易扩展 | 每次操作通常 O(log P)，并非本题首选 | 优先级变化更复杂时 |

## 可能的最优解法

1. 沿用用户方案：频次表、频次层栈和最高频次三个状态已经足够。
2. 不变量一：若某个值当前出现 c 次，它在第 1 到第 c 层各有一条尚未撤销的记录。
3. 不变量二：每层按对应 push 事件的发生顺序存储；最高层的所有记录都是当前合法的最高频候选，层顶事件最新。
4. 弹出最高层栈顶等价于撤销该值最近一次仍有效的入栈事件；其较低层记录保留着正确的旧顺序，所以不用重新入层。
5. 最高层变空时，只需减一：若最高频次原为 f>1，刚弹出的值仍有 f-1 次，其低层记录保证下一层存在；若 f=1，则结构变空。
6. 推荐版本可删除零频键和空层；这是状态清理，不改变原算法及渐近复杂度。

- 时间：push 平均摊还 O(1)，pop 平均 O(1)。每次操作都需要完成常数次必要状态变化，已达最优级。
- 空间：累计 P 次 push 的上界 O(P)。清理后逻辑条目和记录为 O(N)，但 unordered_map 的桶容量可能保留历史规模，不承诺实际分配空间随 N 同步缩小。
- 本题设计接口必须使用 `class FreqStack`，保留 LeetCode 指定类名和构造器；不能改成普通 `class Solution` 提交。

### 推荐 C++20 提交代码

```cpp
class FreqStack {
    unordered_map<int, int> freq;
    unordered_map<int, stack<int>> group;
    int maxFreq = 0;

public:
    FreqStack() = default;

    void push(int val) {
        int currentFreq = ++freq[val];
        // 保存到达该频次的事件；同层栈顶就是最近到达者。
        group[currentFreq].push(val);
        maxFreq = max(maxFreq, currentFreq);
    }

    int pop() {
        auto it = group.find(maxFreq);
        int val = it->second.top();
        it->second.pop();
        if (--freq[val] == 0) {
            freq.erase(val);
        }
        // 低一层的记录已在更早的 push 中保留，不需要重新入栈。
        if (it->second.empty()) {
            group.erase(it);
            --maxFreq;
        }
        return val;
    }
};
```

## 纸面复盘示例

以下只解释状态，不是本次运行测试。

依次 push `[5,7,5,7,4,5]` 后，各层由栈底到栈顶为：

- 第 1 层：`[5,7,4]`
- 第 2 层：`[5,7]`
- 第 3 层：`[5]`

第一次 pop 返回 5，第 3 层变空，最高频次降到 2。第 2 层原有的 `[5,7]` 已表示正确顺序，因此第二次 pop 返回 7，第三次返回 5；接着第 1 层栈顶为 4。这说明降频时若把 5 重新压入第 2 层，反而会错误地让它排到 7 后面。
