- 约束要点：`1 <= points.length <= 10^5`，`-2^31 <= xstart < xend <= 2^31 - 1`（坐标达 int 极限）；区间为闭区间，相切即引爆（箭在 `x=2` 可同时引爆 `[1,2]` 与 `[2,3]`）

## 用户思路概述

1. 对 `points` 按默认字典序排序（即先按左端点升序、再按右端点升序），不写自定义比较器。
2. 维护当前一支箭能覆盖的公共交集 `[l, r]`，初始化为第一个气球区间，答案 `ans` 初始化为 1。
3. 扫描后续气球：若 `points[i][0] > r`，当前交集无法容纳该气球，需要一支新箭，`ans` 加一并重置交集为该气球；否则该气球可与当前箭共存，用 `l = points[i][0]`、`r = min(r, points[i][1])` 收缩交集。
4. 返回 `ans`。

## 用户解法复杂度

- 时间复杂度：`O(n log n)`（排序主导，扫描为 `O(n)`）
- 空间复杂度：`O(log n)`（排序栈，不计输入）
- 复杂度来源：一次完整排序；扫描中只维护 `l`、`r`、`ans` 三个变量。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
public:
    int findMinArrowShots(vector<vector<int>>& points) {
        int n = points.size();
        sort(points.begin(), points.end());   // 默认字典序：左端点升序；不用减法比较，天然避开 int 极限溢出
        int l=points[0][0], r = points[0][1];  // [l, r]：当前一支箭必须落在的公共交集
        int ans = 1;
        for(int i=1; i<n; i++) {
            if(points[i][0] > r) {             // 新气球左端点越过交集右界：旧箭够不到，必须开新箭
                ans ++;
                l = points[i][0], r = points[i][1];
            } else {
                // 闭区间相切也算引爆，所以用 > 而不是 >=；收缩交集保证后续气球仍能被同一支箭覆盖
                l = points[i][0], r = min(r, points[i][1]);
            }
        }
        return ans;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 溢出风险 | 用默认 `sort` 排序 `vector<vector<int>>`，比较器内部只做 `<`，不做减法 | 本题坐标可达 `±2^31`，`a[0]-b[0]` 式比较器会溢出得到错误排序；用户写法天然安全，是重要亮点 | 保持这个习惯：区间端点接近类型极限时，比较器只用 `<` |
| 相切语义 | 判新箭用 `>`，`points[i][0] == r` 时归入当前箭 | 与闭区间"相切即引爆"一致，正确 | 与 435 的 `>=` 对照记忆：一个题相切算重叠、一个不算，比较符方向相反 |
| 交集收缩 | `l = points[i][0]`（排序后左端点递增，等价于 `max`）、`r = min(r, ...)` | 维护的 `[l, r]` 是"当前组所有气球的公共交集"，不变量清晰 | 复盘时能说出：`l` 其实恒等于当前组最后一个气球的左端点，可省略 |
| 空输入假设 | 直接取 `points[0]` | 约束 `n >= 1`，安全；迁移时注意 | 通用模板中显式确认约束后再省略判断 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法（左端点排序 + 维护公共交集） | 交集语义直观；默认排序避开溢出；正确处理相切 | 与 435 的推荐视角不同构，跨题迁移时要多维护一个 `l`；交集思想在"分组覆盖"类题中泛化性稍弱 | 想直观理解"一支箭到底能落在哪里"时很好 |
| 推荐最优解（右端点排序 + 维护箭位置） | 只维护一个变量（箭位置）；与 435 推荐解完全同构，只需把 `>=` 换成 `>`，迁移成本最低 | "箭放在结束最早气球的右端点"需要一句贪心证明 | 区间分组覆盖类题的标准套路 |

## 最优解法

1. 按右端点升序排序；比较器只使用 `<`，避免极端坐标相减溢出。
2. 第一支箭放在排序后首气球的右端点 `arrowPos`，箭数初始化为 1。
3. 扫描后续气球：若 `points[i][0] > arrowPos`，当前箭够不到，开新箭并放到该气球的右端点；否则该气球已被当前箭覆盖，什么都不用改。
4. 返回箭数。

- 关键不变量：`arrowPos` 是当前箭的位置；按右端点排序保证任何与当前组重叠的气球，其左端点若 `<= arrowPos` 就一定被这支箭引爆。
- 贪心理由：结束最早的气球必须被某支箭引爆，把箭放在它的右端点不会比放在更早位置差——右端点是它能覆盖到的"最晚且仍引爆自己"的位置。
- 最优时间复杂度：`O(n log n)`
- 最优空间复杂度：`O(log n)`（排序栈）

### 最优解代码

```cpp
class Solution {
public:
    int findMinArrowShots(vector<vector<int>>& points) {
        // 按右端点升序；比较器只用 <，坐标可达 ±2^31，相减会溢出
        sort(points.begin(), points.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[1] < b[1];
        });
        int arrows = 1;
        int arrowPos = points[0][1]; // 第一支箭放在结束最早气球的右端点
        for (int i = 1; i < static_cast<int>(points.size()); i++) {
            // 闭区间相切即引爆，左端点 == 箭位置仍算覆盖，用 >
            if (points[i][0] > arrowPos) {
                arrows++;
                arrowPos = points[i][1];
            }
        }
        return arrows;
    }
};
```
