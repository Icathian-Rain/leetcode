## 用户思路概述

用户在同一文件里写了两个等价的 `O(n)` 实现，公开接口当前采用 `s2`：

1. `s1`（跳跃式）：从候选起点 `i` 出发模拟绕行，累计油量与耗油；一旦油不够走到下一站，则从 `i` 到失败点的所有位置都不可能是合法起点，直接把候选起点跳到 `i + cnt + 1`。
2. `s2`（前缀最低点）：一遍累加 `balance += gas[i] - cost[i]`，同时记录前缀余额的最低点；若总余额非负，则答案为最低点的下一站；否则返回 `-1`。
3. 公开函数 `canCompleteCircuit` 返回 `s2` 的结果。

## 用户解法复杂度

- 时间复杂度：`O(n)`（两个实现均为单层逻辑：`s1` 虽有嵌套循环，但每个失败区间被整体跳过，起点指针单调推进；`s2` 单趟扫描）
- 空间复杂度：`O(1)`
- 复杂度来源：`s1` 的 `i` 只增不减，`cnt` 消耗的区间不会重复扫描；`s2` 只维护常数个变量。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
    int s1(vector<int>& gas, vector<int>& cost) {
        // 视角一：跳跃式模拟。失败一次即可排除一整段候选起点
        int n=gas.size();
        int i=0;
        while(i < n) {
            int sumOfGas = 0, sumOfCost = 0;
            int cnt = 0;                 // 从 i 出发成功走过的站数
            while(cnt < n) {
                int j=(i+cnt)%n;         // 环形取模
                sumOfGas += gas[j];
                sumOfCost += cost[j];
                if(sumOfCost > sumOfGas) {
                    break;               // 在第 cnt 站后油尽
                }
                cnt ++;
            }
            if(cnt == n) {
                return i;                // 完整绕行一圈
            } else {
                i = i+cnt+1;             // 关键：i..i+cnt 全部不可能，整体跳过
            }
        }
        return -1;
    }

    int s2(vector<int>& gas, vector<int>& cost) {
        // 视角二：前缀最低点。总盈亏非负时，从最低点的下一站出发恰好全程不赤字
        int n=gas.size();
        int minBalance = 0;
        int minIndex = 0;
        int balance = 0;
        for(int i=0; i<n; i++) {
            balance = balance + gas[i]-cost[i];
            if(balance < minBalance) {   // 更新历史最低前缀余额
                minBalance = balance;
                minIndex = i+1;          // 候选起点：最低点的下一站
            }
        }
        return balance >= 0 ? minIndex : -1;  // 总余额非负是有解充要条件
    }
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        // return s1(gas, cost);
        return s2(gas, cost);
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| `s1` 的跳跃正确性 | 失败后跳到 `i+cnt+1` 而非 `i+1` | 这是 `s1` 达到 `O(n)` 的关键：从 `i+1..i+cnt` 出发必然在更早的位置失败（起点油量只会更少），整体排除正确 | 口头证明"为什么失败区间内没有更好的起点"——这是本题最经典的贪心论证 |
| `s2` 的最低点论证 | 前缀最低点的下一站即答案 | 正确：从该站出发，任何后缀前缀余额都非负（最低点已过） | 复盘时把 `s2` 与"后缀和"视角联系：候选站出发的全程余额 = 总和 - 前缀最低点相关项 |
| 有解充要条件 | `balance >= 0` 判定 | 正确使用 `sum(gas) >= sum(cost)` 充要条件 | 已达标 |
| 两种视角并存 | `s1`、`s2` 都正确 | 与 435 的双视角习惯一致，说明"一个题两种证明"已是稳定能力 | 选定 `s2` 提交没问题；面试中 `s1` 的"油尽重置"版本（见最优解）更常被要求现场推导 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户 `s2`（前缀最低点） | 单趟扫描；"最低点下一站"的形象好记 | 论证需要绕一步（最低点与后缀非负的关系），不如油尽重置直接 | 已熟悉前缀和思维时的快速写法 |
| 用户 `s1`（跳跃模拟） | 论证最直接：失败区间整体排除 | 嵌套循环的 `O(n)` 需要摊还解释，初看像 `O(n^2)` | 面试现场推导首选，与推荐最优解同构 |
| 推荐最优解（油尽重置） | 单变量 `tank` + 候选起点，代码最短；`O(n)`/`O(1)` | 无实质缺点 | 本题标准最优形态，也是最容易迁移的版本 |

## 最优解法

1. 一趟扫描，维护 `tank`（从当前候选起点出发的剩余油量）与 `total`（全局总盈亏）。
2. 每站 `tank += gas[i] - cost[i]`；若 `tank < 0`，则当前候选起点到 `i` 都不可行，重置候选起点为 `i+1` 并清零 `tank`。
3. 扫描结束：`total >= 0` 则候选起点即答案，否则返回 `-1`。
- 关键不变量：候选起点 `start` 之前的任何位置出发都无法越过最后失败的那一站，故重置是安全的；`total >= 0` 保证最终候选起点可行（若 `total < 0` 则全局无解）。
- 最优时间复杂度：`O(n)`
- 最优空间复杂度：`O(1)`

### 最优解代码

```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = static_cast<int>(gas.size());
        int tank = 0;   // 从当前候选起点出发的剩余油量
        int total = 0;  // 全局总盈亏，判定有解充要条件
        int start = 0;
        for (int i = 0; i < n; i++) {
            int diff = gas[i] - cost[i];
            tank += diff;
            total += diff;
            if (tank < 0) {
                // start..i 内任何起点都过不了 i，整体排除后重置
                start = i + 1;
                tank = 0;
            }
        }
        return total >= 0 ? start : -1;
    }
};
```
