## 基本信息

- 难度：简单

- 对应源码：[src/605.can-place-flowers.cpp](../src/605.can-place-flowers.cpp)
- 资料来源：[LeetCode 中国版官方题目页](https://leetcode.cn/problems/can-place-flowers/)，2026-11-13 查询
- 约束要点：`1 <= flowerbed.length <= 2*10^4`，`0 <= n <= flowerbed.length`；输入保证无相邻花；边界外侧视为空地

## 用户思路概述

1. 维护 `pre`（上一朵已种花的位置，虚拟初始化为 `-2` 让开头段公式与中段统一）、`sum`（已统计的可种数）。
2. 扫描遇到已种花 `i` 时，计算它与前一朵花之间的空位可种数：`total = i - pre - 3`（即空位数减 2），`sum += (total + 1) / 2`；提前达标即返回 `true`，然后 `pre = i`。
3. 扫描结束后，处理末尾段（`pre` 之后到数组末尾，无右花约束）：`sum += (len - 1 - pre) / 2`，再与 `n` 比较。
4. 返回是否至少能种 `n` 朵。

## 用户解法复杂度

- 时间复杂度：`O(m)`（`m` 为数组长度，单趟扫描）
- 空间复杂度：`O(1)`
- 复杂度来源：单趟扫描，只维护两个整型变量。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
public:
    bool canPlaceFlowers(vector<int>& flowerbed, int n) {
        int len = flowerbed.size();
        int pre = -2;  // 上一朵花的位置；-2 是虚拟值，让开头段套用中段公式
        int sum = 0;
        for(int i=0; i<len; i++) {
            if(flowerbed[i] == 1) {
                // 两花之间空位 gap = i-pre-1，两侧各留一格，可种 (gap-1)/2 = (i-pre-3+1)/2
                int total = i - pre - 3;
                sum += (total+1)/2;
                if(sum >= n) return true;   // 提前达标剪枝
                pre = i;
            }
        }
        // 末尾段无右侧花约束：pre 到末尾共 len-1-pre 个空位，可种一半
        return sum + (len-1-pre)/2 >= n;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 段计数公式 | 中段 `(gap-1)/2`、开头段（虚拟 `pre=-2`）、末尾段三处公式均正确 | 用“段”而非“格”做统计，一次推演即得整段可种数，是比逐格贪心更概括的视角，经推演正确 | 三处公式来源不同（中段两侧受限、开头末尾单侧受限），值得各写一句推导，防止下次凭记忆写错 |
| `pre = -2` 的虚拟初始化 | 选 `-2` 使开头段套用中段公式 | 巧妙但隐晦：读者需要自行验证 `i=0` 时 `total=-1`、`(total+1)/2=0` 仍正确 | 复盘时在代码旁写一句"为什么是 -2 不是 -1"，检验自己能否说清 |
| `n = 0` 边界 | `sum >= n` 在循环内可提前返回；全 0 数组走末尾公式 | 正确覆盖 | 已达标 |
| 可读性 | 公式压缩了逐格判断 | 次要级问题：`(total+1)/2` 这类表达式复盘时需要重新推导 | 逐格贪心版本（见最优解）更直白，两者复杂度相同，按场合取舍 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法（段计数） | `O(m)`/`O(1)`；按段统计一次算整段，扫描量与判断次数少 | 三处公式各自推导，出错面比逐格判断大；`pre=-2` 需要解释 | 熟悉公式推导后的快速写法 |
| 推荐最优解（逐格贪心跳 2） | 逻辑直白：能种就种、种完跳 2 格；无段落公式要背 | 无实质缺点 | 首选写法，尤其面试中解释成本低 |

## 最优解法

1. 从左到右扫描，维护计数 `count`。
2. 位置 `i` 能种当且仅当：自身为 0、左邻居（越界视为 0）为 0、右邻居（越界视为 0）为 0。
3. 能种则 `count++` 并跳到 `i+2`（`i+1` 必然不可种）；不能种则 `i++`。
4. 返回 `count >= n`。
- 关键不变量：能种就立即种不会损失最优——最左边可行位置种下后，右侧可种位置只会更多不会更少（交换论证）。
- 最优时间复杂度：`O(m)`
- 最优空间复杂度：`O(1)`

### 最优解代码

```cpp
class Solution {
public:
    bool canPlaceFlowers(vector<int>& flowerbed, int n) {
        int len = static_cast<int>(flowerbed.size());
        int count = 0;
        for (int i = 0; i < len; i++) {
            // 左右邻居越界视为空地（0）
            int left = (i == 0) ? 0 : flowerbed[i - 1];
            int right = (i == len - 1) ? 0 : flowerbed[i + 1];
            if (flowerbed[i] == 0 && left == 0 && right == 0) {
                count++;
                i++; // 种下后右邻格必然不可种，再跳一格到 i+2
            }
        }
        return count >= n;
    }
};
```

## 对比与改进方向

| 对比项 | 用户代码 | 最优解代码 | 改进方向 |
| --- | --- | --- | --- |
| 状态定义 | `pre` + `sum` 段统计 | `count` + 当前格判断 | 段统计概括力强，逐格判断解释成本低 |
| 更新逻辑 | 遇花结算一段 | 能种即种、跳 2 格 | 两者等价，复杂度相同 |
| 边界处理 | 虚拟 `pre=-2` 统一开头段 | 越界邻居显式置 0 | 逐格版边界更不易写错 |
| 复杂度 | 时间 `O(m)`、空间 `O(1)` | 相同 | 已达最优 |
