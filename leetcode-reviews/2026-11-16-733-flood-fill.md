- 日期：2026-11-16
- 主题：第 11 周图论 BFS 与 DFS - 图遍历入口
- 难度：简单
- 本次结果：通过（用户确认已测试通过）
- 对应源码：[src/733.flood-fill.cpp](../src/733.flood-fill.cpp)
- 资料来源：[LeetCode 中国版官方题目页](https://leetcode.cn/problems/flood-fill/)，2026-11-16 查询
- 约束要点：`1 <= m, n <= 50`，`0 <= image[i][j], color < 2^16`；新颜色等于原颜色时图像不做任何更改（必须显式处理，否则死循环）

## 用户思路概述

1. 先取起点原色 `raw_color`；若 `raw_color == color` 直接返回，避免无意义扩散（也避免死循环）。
2. BFS：起点入队并立即改色（入队即"标记"）；每轮出队一个像素，向四个方向扩展。
3. 邻居在界内且颜色仍为原色时，入队并立即改色——改色即访问标记，天然防止重复入队。
4. 队列空即扩散完成。

## 用户解法复杂度

- 时间复杂度：`O(m × n)`（每个格子最多入队一次）
- 空间复杂度：`O(m × n)`（队列最坏情况，如整图同色）
- 复杂度来源：每格至多被 4 个邻居各检查一次；入队即改色保证无重复。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
using pii = pair<int, int>;
const int DIRECT[][2] = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
class Solution {
public:
    vector<vector<int>> floodFill(vector<vector<int>>& image, int sr, int sc, int color) {
        int m=image.size(), n=image[0].size();
        int raw_color = image[sr][sc];
        if(raw_color == color) {
            return image;   // 原色即新色：不改图，也避免"改色即标记"失效导致死循环
        }
        queue<pii> q;
        q.emplace(sr, sc);
        image[sr][sc] = color;   // 入队即改色：颜色本身就是访问标记
        while(!q.empty()) {
            auto [px, py] = q.front(); q.pop();
            for(int i=0; i<4; i++) {
                int nx = px+DIRECT[i][0], ny = py+DIRECT[i][1];
                if(nx >= 0 && nx < m && ny >= 0 && ny < n && image[nx][ny] == raw_color) {
                    q.emplace(nx, ny);
                    image[nx][ny] = color;   // 入队同时改色，防止重复入队
                }
            }
        }
        return image;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 原色==新色短路 | 开头显式判断并返回 | 关键边界处理正确：此时若继续 BFS，`image[nx][ny] == raw_color` 永远成立，无限扩散 | 已达标；这是本题官方样例 2 专门考察的陷阱 |
| 改色即标记 | 不用 visited 数组，直接改写原图 | 正确且省空间：颜色变化本身就是访问标记，是网格 BFS 的常用技巧 | 想清"什么时候可以借用原图当标记"——当修改后的值不再满足扩展条件时 |
| 入队即改色 vs 出队改色 | 入队时改色 | 正确：出队才改色会让同一格被多个邻居重复入队；用户注释掉的 `// image[px][py] = color;` 说明思考过这个位置 | 已达标；这个被注释的行正是两种写法的分界点，值得口头复述原因 |
| 方向数组 | 全局 `DIRECT` 常量 | 与 200 题共享同一套写法，网格题代码风格统一 | 已达标 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法（BFS + 原图当标记） | `O(mn)`/`O(mn)`；无递归栈风险；改色即标记省一个数组 | 修改了输入（本题允许，返回值就是图） | 网格扩散类标准写法 |
| 递归 DFS | 代码更短 | `m,n <= 50` 无风险，但大规模网格有栈深问题 | 小网格或习惯递归时 |
| 保留 visited 数组 | 不改输入 | 多 `O(mn)` 空间；本题必须返回改后图，无收益 | 输入不可修改时 |

## 最优解法

1. 取原色；原色等于新色直接返回。
2. BFS 从起点扩散：入队即改色（颜色即标记），四方向邻居为原色则入队并改色。
3. 队列空结束。
- 关键不变量：队列中永远是"已改色待扩展"的像素；扩展条件"仍为原色"与"已改色"互补，保证每格至多入队一次。
- 最优时间复杂度：`O(m × n)`
- 最优空间复杂度：`O(m × n)`（队列最坏）

### 最优解代码

```cpp
class Solution {
public:
    vector<vector<int>> floodFill(vector<vector<int>>& image, int sr, int sc, int color) {
        int m = static_cast<int>(image.size());
        int n = static_cast<int>(image[0].size());
        int raw = image[sr][sc];
        if (raw == color) return image; // 原色即新色：不改图，也避免死循环
        queue<pair<int, int>> q;
        q.push({sr, sc});
        image[sr][sc] = color; // 入队即改色，颜色即访问标记
        const int dx[] = {1, -1, 0, 0}, dy[] = {0, 0, 1, -1};
        while (!q.empty()) {
            auto [x, y] = q.front(); q.pop();
            for (int i = 0; i < 4; i++) {
                int nx = x + dx[i], ny = y + dy[i];
                if (nx >= 0 && nx < m && ny >= 0 && ny < n && image[nx][ny] == raw) {
                    image[nx][ny] = color; // 入队同时改色，防止重复入队
                    q.push({nx, ny});
                }
            }
        }
        return image;
    }
};
```
