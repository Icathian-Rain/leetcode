- 难度：困难

- 资料来源：[LeetCode 中国版官方题目页](https://leetcode.cn/problems/word-ladder/)，2026-11-21 查询
- 约束要点：`1 <= wordList.length <= 5000`，`1 <= 单词长度 <= 10`；beginWord 不必在列表中；返回序列**单词数**（含首尾）；endWord 不在列表返回 0

## 用户思路概述

1. 显式建图：`cmp` 判定两词是否至多差一个字母（超过 1 提前剪断）；对词表所有对 `(i, j)` 建双向边，`O(n² · L)` 预处理。
2. `beginWord` 不占编号：用虚拟节点 `n` 表示它——词表单词与 beginWord 至多差一时，从词表词连向 `n`。
3. `endWord` 定位为 BFS 起点（`dist[start] = 1`），向虚拟节点方向搜——命中 `adj[p][j] == n` 即到达 beginWord，返回 `dist[p] + 1`（单词数口径）。
4. endWord 不在词表返回 0；队列耗尽返回 0。

## 用户解法复杂度

- 时间复杂度：`O(n² · L)` 建图 + `O(n + e)` BFS（`e` 最坏 `O(n²)`）
- 空间复杂度：`O(n²)` 邻接表最坏
- 复杂度来源：全对比对建图是瓶颈；`n = 5000` 时对数约 1.25×10⁷、每次比较最长 10 字符，总量约 10⁸ 级字符比较——本题能过但已接近上限，是主要的性能风险点。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        int n=wordList.size();
        vector<vector<int>> adj(n);   // beginWord 用虚拟编号 n 表示，不占词表下标
        auto cmp = [](const string& a, const string& b) -> bool {
            int len=a.size();
            int diff=0;
            for(int i=0; i<len; i++) {
                if(a[i] != b[i]) {
                    diff++;
                    if(diff > 1) {
                        return false;   // 剪枝：第二处不同即判否
                    }
                }
            }
            return true;
        };
        int start = -1;
        for(int i=0; i<n; i++) {
            if(wordList[i]==endWord) {
                start = i;             // BFS 起点：endWord（反向搜）
            }
            for(int j=i+1; j<n; j++) {
                if(cmp(wordList[i], wordList[j])) {
                    adj[i].push_back(j);
                    adj[j].push_back(i);
                }
            }
            if(cmp(wordList[i], beginWord)) {
                adj[i].push_back(n);   // 词表词 -> 虚拟 beginWord 节点
            }
        }
        if(start == -1) return 0;      // endWord 不在词表：直接失败
        vector<int> dist(n, -1);
        queue<int> q;
        q.push(start);
        dist[start] = 1;               // 单词数口径：起点即 1
        while(!q.empty()) {
            auto p=q.front(); q.pop();
            for(int j=0; j<adj[p].size(); j++) {
                if(adj[p][j] == n) return dist[p]+1;  // 命中虚拟节点即完整序列
                if(dist[adj[p][j]] == -1) {
                    q.push(adj[p][j]);
                    dist[adj[p][j]] = dist[p]+1;
                }
            }
        }
        return 0;
    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 虚拟节点建模 | beginWord 用编号 `n` 表示，不混入词表 | 优雅地处理"beginWord 不一定在列表"的题面条件，避免插入/删除词表的边角处理 | 归纳一句：图中不便于入队的节点用虚拟编号挂边即可 |
| 反向 BFS | 从 endWord 搜向 beginWord | 正确且与正向等价；从 endWord 出发让"到达虚拟节点"自然成为终点判定 | 意识到方向可换即可，正向版需要单独的终点比较 |
| 单词数口径 | `dist[start] = 1`，命中时 `+1` | 正确对齐"返回单词数而非步数"的口径 | 与 1091 同日出现两个"计数口径"题，值得并排记忆 |
| 建图复杂度 | 全对比对 `O(n²L)` | 主要级性能风险：`n=5000` 逼近上限；预排序或通配模式可降到 `O(N·L²)` 级 | 见下表最优解——这是本题与"能过"之间真正差的一档 |
| `cmp` 的命名 | 单词大小判定用了排序语境的名字 | 次要级问题：`differByAtMostOne` 之类更达意 | 命名跟进语义 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法（全对建图 + 反向 BFS） | 思路直白；建图一次全程使用；虚拟节点处理干净 | `O(n²L)` 建图在 `n=5000` 时偏重 | 词表较小时（本题规模勉强可行） |
| 通配模式建图（`h*t` → 邻接桶） | `O(N·L²)` 级；词表大时显著更快；免两两比较 | 需要"逐位替换生成 26 邻居"或"通配中间态"的建模转换 | 词表大的标准做法 |
| 双向 BFS | 从两端同时搜，相遇即答案，常数大幅降低 | 实现细节多一套 | 追求极致时（本题单 BFS 已达量级最优） |

## 最优解法

1. 词表存入哈希集合；为每个词生成通配中间态（如 `hot` → `*ot, h*t, ho*`），通配态 → 词表词建桶。
2. BFS 从 beginWord 出发：出队一词，枚举其全部通配态，桶内所有词均为 1 距邻居，访问后从集合删除（删除即标记）。
3. 首达 endWord 返回层级（单词数口径）。
- 关键不变量：两词至多差一字母 ⟺ 共享同一通配中间态——比较关系转成桶里的共享关系。
- 最优时间复杂度：`O(N × L²)`（每词 L 个通配态、每态 build/查询 O(L)）
- 最优空间复杂度：`O(N × L²)`

### 最优解代码

```cpp
class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        // 哈希集合：O(1) 查存在，删除即"已访问"
        unordered_set<string> dict(wordList.begin(), wordList.end());
        if (!dict.count(endWord)) return 0;
        dict.erase(beginWord); // beginWord 不占位（若在表中）
        queue<pair<string, int>> q; // (当前词, 已用单词数)
        q.push({beginWord, 1});
        while (!q.empty()) {
            auto [word, steps] = q.front(); q.pop();
            // 逐位替换 26 个字母生成邻居：与当前词恰好差一个字母全体
            for (int i = 0; i < static_cast<int>(word.size()); i++) {
                char origin = word[i];
                for (char c = 'a'; c <= 'z'; c++) {
                    word[i] = c;
                    if (word == endWord) return steps + 1; // 首达即最短，单词数口径
                    if (dict.count(word)) {
                        dict.erase(word); // 删除即标记，防止重入
                        q.push({word, steps + 1});
                    }
                }
                word[i] = origin; // 恢复被替换位
            }
        }
        return 0;
    }
};
```

## 对比与改进方向

| 对比项 | 用户代码 | 最优解代码 | 改进方向 |
| --- | --- | --- | --- |
| 建模方式 | 全对比对显式建图 | 通配态/逐位替换隐式生成邻居 | 把"比较两词"翻成"共享中间态"，复杂度差一个 `n` 因子 |
| 状态定义 | 虚拟节点 + dist 数组 | 哈希集合删除即标记 | 集合删元是空间更省的标记载体（第 6 种形态） |
| 更新逻辑 | 反向 BFS + 命中虚拟节点 | 正向 BFS + 出队时比较终点 | 双向等价，正向实现少一个虚拟节点 |
| 边界处理 | endWord 缺失返回 0 正确 | 相同 | 已达标 |
| 复杂度 | 时间 `O(n²L)`、空间 `O(n²)` | 时间 `O(N·L²)` | 词表大时差距显著 |
