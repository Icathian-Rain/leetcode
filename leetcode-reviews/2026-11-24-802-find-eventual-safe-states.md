- 约束要点：`1 <= n <= 10^4`；边数 `[1, 4×10^4]`；**图中可能含自环**；答案需升序

## 用户思路概述

1. 建反图 `rg[v] = 指向 v 的节点`；`inDeg[u]` 实际存的是 u 的**出度**（后继数）——昨天入度清零的镜像。
2. 出度为 0 的终端节点先入队；处理 y 时将其每个前驱 x 的剩余出度减 1，减到 0 则入队（全部后继已确定安全）。
3. 队列耗尽后，最终扫描收集所有剩余出度为 0 的节点——升序天然成立（按编号顺序扫描）。
4. 不需要单独的安全标记：出度归零的终态本身就是"安全"的判定。

## 用户解法复杂度

- 时间复杂度：`O(V + E)` + 终态扫描 `O(V)`，总量 `O(V + E)`
- 空间复杂度：`O(V + E)`（反图 + 度数数组 + 队列）
- 复杂度来源：反图拓扑的标准形态；每条边只引发一次出度递减。

## 用户代码注释版

> 只在点评文档中展示加注释版本；不把这些注释写回 `src/*.cpp` 的用户原代码。

```cpp
class Solution {
public:
    vector<int> eventualSafeNodes(vector<vector<int>>& graph) {
        int n=graph.size();
        vector<vector<int>> rg(n);
        vector<int> inDeg(n);
        for(int u=0; u<n; u++) {
            for(auto v: graph[u]) {
                rg[v].push_back(u);      // 反图：v 的前驱列表加入 u
            }
            inDeg[u] = graph[u].size();  // 这里实际是“出度”（joker 命名：变量名叫入度，存的是出度）
        }
        queue<int> q;
        for(int i=0; i<n; i++) {
            if(inDeg[i] == 0) {           // 终端节点：无后继，天然安全
                q.push(i);
            }
        }
        while(!q.empty()) {
            int y=q.front();q.pop();
            for(auto x: rg[y]) {          // 所有指向 y 的前驱
                inDeg[x]--;               // x 的一个后继被确认安全
                if(inDeg[x] == 0) {      // x 的后继全部安全：x 也安全
                    q.push(x);
                }
            }
        }
        vector<int> ans;
        for(int i=0; i<n; i++) {
            if(inDeg[i] == 0) {           // 出度归零留下的全体 = 安全节点集；按编号扫描即升序
                ans.push_back(i);
            }
        }
        return ans;


    }
};
```

## 关键理解点

| 理解点 | 用户当前表现 | 影响 | 建议 |
| --- | --- | --- | --- |
| 镜像建图（反图 + 出度） | 建反图、以出度为"待满足计数" | 完全命中本题核心：安全 = 从 x 出发不碰环 ⟺ x 的所有后继都安全，所以沿"后继确认"方向倒推——清零方向从昨天的"先修满足"翻转成"后继安全" | 归纳一句：拓扑清零的方向跟着"条件谁先齐"走，正图入度与反图出度是同一骨架的两面 |
| 变量命名 | `inDeg` 存的实为出度 | 功能正确，但对读者与迁移者是误导——自己在复盘里也可能被它绊一次 | 次要级问题：换名 `outDeg`/`remain` 即可，语义与用途对齐 |
| 安全判定即度数终态 | 不设 safe 数组，靠终态 `inDeg==0` 收集 | 优雅：处理后的度数数组本身就是答案的过滤器 | 意识到两处 `inDeg[x]==0` 的含义不同——队首的判空是"待扩展"，终态扫描的判空是"结论"，同一条件两种时刻两种角色 |
| 自环处理 | 出度含自环边，节点的自指需要自己处理来归零 | 正确：自环节点永远等不到"全部后继安全"（自己也未安全），除非被队列处理——而它入队又要求自己已安全，形成死锁 ⟹ 永不安全 | 复述一遍自环为什么被自动排除，这是官方约束特意提醒的陷阱 |

## 算法优缺点

| 方案 | 优点 | 缺点 | 适用情况 |
| --- | --- | --- | --- |
| 用户解法（反图 + 出度清零） | `O(V+E)` 最优；度数终态即答案 | 无实质缺点 | 本题的标准解 |
| DFS 三色染色 | 找环路径更直接 | `n=10^4` 递归深度有风险需显式迭代；代码更长 | 需要具体环信息时 |
| 正图 DFS + 状态缓存 | 免建反图 | 递归同上 | 迭代化后可用的等价脉络 |

## 最优解法

1. 反图 + 出度数组；终端节点（出度 0）先入队。
2. 出队 u 时对反图中所有前驱的出度减 1，归零者入队（全部后继安全 ⟹ 自身安全）。
3. 结束后收集出度为 0 的节点（或直接用出队序列 + 排序兜底）。
- 关键不变量：**节点入队当且仅当其全部后继均已确定安全**；能到达环的节点其出度永远无法归零（环上互相等待）。
- 最优时间复杂度：`O(V + E)`
- 最优空间复杂度：`O(V + E)`

### 最优解代码

```cpp
class Solution {
public:
    vector<int> eventualSafeNodes(vector<vector<int>>& graph) {
        int n = static_cast<int>(graph.size());
        vector<vector<int>> rg(n);         // 反图：rg[v] = 指向 v 的节点列表
        vector<int> out(n, 0);              // 每个节点尚待确认安全的后继数
        for (int u = 0; u < n; u++) {
            for (int v : graph[u]) rg[v].push_back(u);
            out[u] = static_cast<int>(graph[u].size());
        }
        queue<int> q;
        for (int i = 0; i < n; i++) {
            if (out[i] == 0) q.push(i); // 终端节点：无后继，天然安全
        }
        vector<int> ans;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            ans.push_back(u); // 出队即确定安全
            for (int v : rg[u]) { // 反图收敛：v 的一个后继确认安全
                if (--out[v] == 0) q.push(v); // v 全部后继安全 -> v 也安全
            }
        }
        sort(ans.begin(), ans.end()); // 出队序通常即升序；sort 兜底一次 O(n log n)
        return ans;
    }
};
```

> 说明：出队序在按编号初始化队列时并非严格升序（同层节点的处理顺序混编，后继确认可能乱序），故安全起见补一次排序；用户按编号终态扫描的写法天然有序，二者等价。
